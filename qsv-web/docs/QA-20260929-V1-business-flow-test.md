日期：2026-09-29（Asia/Taipei）  
范围：V1 的 P01—P16 页面与可运行的核心业务路径。PRD 中列出的每一种格式、规则和边界情况没有全部逐项执行；未覆盖内容在下表注明。

## 测试环境

- Web：`http://localhost:5273`；API：`http://localhost:5274`；Node.js 24.11.1。
- 固定引擎：qsv 23.0.1，SHA-256 `82f5ae1cb2069c3acbee487d533501afa782470be0f9231ff54a01dbf4517fd7`。
- 浏览器：Codex 内置浏览器。当前会话没有可调用的 `@浏览器` 插件工具，因此通过内置浏览器完成页面操作；外部 Playwright 命令也不可用。
- 测试数据：本机临时私有目录中的订单、发货和格式异常 CSV。没有修改原有用户数据。资源回收站测试使用刚生成的 `qa-export-range.csv`，操作后已恢复。

### 本机启动限制

仓库文档中的 `pnpm dev:server` 在本机 Node 24.11.1 下不能直接启动。Node 的 TS strip-only 模式不支持服务端源码中的 parameter property；加 `NODE_OPTIONS=--experimental-transform-types` 后，`iconv-lite` 和 `node-sql-parser` 的 CommonJS 命名导入仍无法解析。为启动本轮浏览器测试，我在 `/tmp` 使用临时 loader 提供导入桥接，并跳过 `apps/server/src/app.ts` 中重复注册的旧版 `GET /api/v1/recipes` 501 路由。仓库源码没有为此修改。详细条目见 [BUG-20260929-001](BUG_TRACKER.md) 和 [BUG-20260929-002](BUG_TRACKER.md)。

## 发现的问题

1. **本机服务启动链路有多处阻断。** Node 24 的 TS strip-only 模式不支持 parameter property；打开 transform 后，CommonJS 包命名导入仍失败；桥接导入后 Fastify 又因重复的 `GET /api/v1/recipes` 退出。浏览器测试依赖 `/tmp` 临时 loader 才能进行。见 BUG-20260929-001、BUG-20260929-002。
2. **共用提示条在 warning 状态下崩溃。** `/join` 首屏可复现；`JoinPage`、`ConvertPage`、`BatchExportPanel`、`RecipesPage`、`ComparePage` 和 `CompareResultPage` 中还有多个 `tone="warning"` 调用。`Banner` 实际只定义 `info`、`ok`、`warn`、`danger`。见 BUG-20260929-003。
3. **语言选择框出现两个箭头，已修复。** 全局 `select` 已关闭浏览器原生箭头，保留项目绘制的箭头；本机浏览器热更新后只显示一个箭头，中英文切换正常。见 BUG-20260929-004。
4. **核对预检完成后提交被拒绝。** P09 的浏览器路径可稳定走到预检结果，提交时返回 `PREFLIGHT_STALE`。初步定位为比较页总会发送、但提交接口 schema 未声明的配置字段，需复核后修复。见 BUG-20260929-005。
5. **合法 SELECT 查询被拒绝。** 当前 `node-sql-parser` 解析普通 SELECT 时会返回 `into: { position: null }`；验证器将任何非 null 的 `into` 判作写出语法。见 BUG-20260929-006。
6. **类型检查未通过。** `pnpm typecheck` 报告多处 TypeScript 错误，包括缺少路由必需的 `search` 参数、可空值未收窄和 `warning` 不属于提示条 tone 类型。见 BUG-20260929-007。

## 补充命令校验

- `pnpm test:web`：通过，1/1。
- `pnpm typecheck`：失败；存在多处既有类型错误，详见 BUG-20260929-007。样式箭头修改本身已在浏览器验证。
- `pnpm test:server`：默认运行时 8/10 个测试文件因 Node 24 strip-only 模式不支持 parameter property 而失败。设置 `NODE_OPTIONS=--experimental-transform-types` 后，仍有 8/10 个文件因 `iconv-lite` 没有 ESM 命名导出 `decode` 而失败；2 个独立测试通过。
