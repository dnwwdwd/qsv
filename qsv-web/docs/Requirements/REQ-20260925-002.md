## 背景、目标与边界

用户要求：按 PRD 与 PPD 开始做前端页面，**暂不与 qsv 底座对接**，页面数据全部为 mock；布局合理、配色干净清爽、PC 端适配、菜单按功能分组、响应快。

本轮交付：一个可运行的 React 单页应用，覆盖 PRD 第 5 节列出的 V1 全部 16 个页面入口（P01—P16），
页面按真实接口的形态编写（异步、加载、错误、范围、版本），数据来自浏览器内存中的 mock 层。

明确不做：
- 不写任何后端、Fastify 服务、SQLite、迁移、文件读写与懒猫部署产物；不修改 qsv 的 Rust 代码与原有 `docs/`。
- 不做 V2 的 AI 助手、Agent 与模型设置入口（用户本轮明确"暂时只做 V1"，界面上不出现这些入口）。
- 不承诺性能数字：PRD 第 11 节的 NFR 目标是验收目标，本轮只保证演示数据下的交互流畅与内存有界，未做真机实测。
- 不做英文界面与深色主题（PRD 要求中文必需、英文可切换；本轮只交付中文）。

## 方案与依赖

- 工作区放在 `qsv-web/`，不污染 Rust 根工程；前端只依赖 `apps/web` 内的包。
- 设计系统先落地再写页面：OKLCH 令牌与基础组件（`src/ui/`），页面只复用组件与令牌，禁止任意样式值。
- 百万行浏览按 PPD 第 8 节实现：行块接口语义 + 有界虚拟滚动 + 已加载区间标尺 + 全局行号跳转；浏览器内存不随"累计滚过的行数"增长。
- 双表核对按 PRD 第 6 节 P09/P10 与第 10 节黄金样例实现，金额用定点整数比较，不做浮点换算，两侧数量守恒逐项校验。
- 后续接入真实 API 时，页面结构不变，替换 `src/mock/api.ts` 的实现即可；届时需重新确认数据方案（DEC-20260925-001 仍待确认）。

## 与 PRD/PPD 的差异记录

- PRD 第 5 节把页面合并方式留给实现；本轮一个页面一个路由，路由与编号一一对应，便于按需求逐条验收。
- PRD 要求英文可切换，本轮只做中文；已记入 UI_GUIDE 的"已知未决"。
- PPD 第 2.1 节的仓库结构把 `apps/web` 放在仓库根；本仓库根是 Rust 工程，实际放在 `qsv-web/apps/web`，其余目录约定不变。
- **内容克制的取舍（用户要求"只保留核心功能"）**：以下 PRD 能力在本轮界面中被压缩或移出主流程，接真实实现时需要补回或另找入口：
  - P01：未提交配置的独立区块（V1-HOME-04）改由顶栏/资源页入口承接，本轮未在首页展示；内置示例入口未做。
  - P03：JSON 数据路径、数组处理、缺字段与类型冲突策略、解析配置复用面板未在界面展开（V1-IMP-08、V1-IMP-14）；
    字段与类型确认表压缩为前 8 列。
  - P04：单元格修正改为在"单元格"页签内联提交（V1-DATA-08 保留能力，界面更简）；版本对比入口指向 P09。
  - P06：编码/分隔符/引号等参数按格式各保留 3 项；逐文件覆盖配置未做（V1-CONV-01 部分）。
  - P07：输出列配置与字段对齐检查表压缩为一行结论（V1-JOIN-06 部分）。
  - P08：Sheet 拆分与部分参数策略改为按模式显示，未同时铺开（V1-SPLIT-03 保留入口）。
  - P11：规则新增与"从字段类型生成建议"未在界面提供（V1-VAL-01、V1-VAL-05）；Schema 导入导出压成一行。
  - P12：透视参数矩阵压成一行提示（V1-ANA-04 部分）；字段概览大表未做。
  - P15：步骤明细与部分日志默认折叠（V1-JOB-03、V1-JOB-10 仍可展开查看）。
  - P16：管理员上限并入引擎区块一行；操作清单与风险等级未展示。
- 这些取舍是演示阶段的界面取舍，不代表需求被删除；接真实实现时按 PRD 逐条补齐。
- **P04 窄屏交互（2026-09-26 用户确认）**：宽度 <1280 时，字段/视图/单元格/版本检查器由"右侧常开"改为"底部抽屉默认收起"，
  点表格行、点单元格全文或点页签时自动展开；≥1280 仍为右侧常开。原因是窄屏下表格与检查器各占一半高度，
  百万行表格只剩 8 行可见。该行为属于演示阶段的布局取舍，接真实实现时可保留或改为独立页面。
- **页面顶部结构（2026-09-26 用户确认）**：删除每个页面顶部的白底页头区块，标题、关键事实、本页控件与主操作合并成一条顶部横条；
  页面说明句改为标题的悬浮提示。这是用户明确要求的界面结构变更，接真实实现时沿用。
