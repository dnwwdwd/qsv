## 背景、目标与边界

现有仓库以 Rust CLI 为主，入口、命令模块与测试分别位于 `src/main.rs`、`src/cmd/`、`tests/`；没有按 PRD 提供完整 Web 应用。目标是让用户在浏览器中使用 qsv 的受限、可追溯数据处理能力。PRD 规划 V1 非 AI 工作流，V2 再增加可关闭的 AI 功能。

本次任务只完成文档初始化与归档，不修改 CLI 行为，不创建 Web 应用、API、数据库、迁移或部署产物。PRD 中的页面编号和工作流是后续验收依据，不代表已经实现。产品命名、UI 设计、固定 qsv 二进制能力、实际平台兼容和性能数字仍待实施时验证。

## 方案与依赖

本次沿用 qsv 上游 `docs/`；Web 产品文档统一放在 `qsv-web/docs/`。根目录 `DOCUMENT_MAP.md` 是路径索引，根目录 `AGENTS.md` 记录协作规则。未来实现先做 PPD 第 18 节的能力验证，再在具体阶段确认数据和接口方案，按可验证的功能片段开发。

PPD 第 1—3 节的技术选型、第五节的三表数据模型和第 13 节的部署设想均是设计基线。数据库 schema、迁移、数据访问代码及依赖它们的 API/UI 必须在用户明确确认书面数据方案后才能编写。当前无数据库操作，也无真实数据迁移。
