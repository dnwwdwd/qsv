# DEC-20261011-005：懒猫 OIDC 登录入口与身份来源

- 日期：2026-10-11
- 状态：已实施并在本机用 stub 提供方端到端验证；懒猫真机未验证
- 关联：REQ-20260926-003、BUG-20261011-006、007、008

## 用户要求

必须提供登录页面，用户完成懒猫 OIDC 登录之后才可以使用工作台功能。

## 身份来源：只用 OIDC 会话

用户明确选择「严格只用 OIDC 会话」。因此：

- 服务端在 `AUTH_MODE=lazycat` 下**只**通过 `OidcAuth` 的会话 cookie 认定身份，会话来自标准授权码流程（PKCE + state + nonce，`openid-client` 校验 issuer/audience/签名）。
- **不接受**入口注入的 `X-HC-User-ID` / `X-HC-User-Role` 作为身份来源。懒猫技能文档允许后端直接信任这些请求头，本应用出于更严格的边界选择不采用；代价是必须完成一次应用内 OIDC 登录，不能只依赖平台已登录状态免跳转。
- `owner_key` 仍按 PPD 从已验证的 `(issuer, subject)` 派生，与文件路径的 opaque workspace ID 绑定。

为了让测试可注入身份，同时不引入线上旁路：身份提供者抽成 `AuthProvider` 接口；生产只用 `OidcAuth`，测试用 `src/test-auth.ts` 的 `StubAuth`。`main.ts` 只构造 `OidcAuth`，永不构造 `StubAuth`。

## 登录入口与放行规则

- 新增前端 `/login` 页面：懒猫 OIDC 登录按钮、失败原因提示、界面语言跟随现有设置。
- 未登录行为：页面路由（含深链接）302 到 `/login`；`/api/*` 返回 401；带扩展名的静态构建产物放行（登录页自身需要它们）。这些放行路径不返回任何用户数据。
- 免鉴权路径仅 `/health`、`/login`、`/auth/*`。
- 回调失败不再直接返回错误页，而是跳 `/login?authError=…`，由登录页展示原因。
- 应用来源优先取 `QSV_APP_ORIGIN`；懒猫部署由 manifest 注入 `https://{{ .S.AppDomain }}`（与 `lazycat-search` 等既有项目一致）。缺少来源时拒绝启动，避免真机静默失败。

## 本机验证的受控放宽

`openid-client` 默认只允许 HTTPS。为在本机跑通真实链路，新增 `QSV_OIDC_ALLOW_INSECURE=1`：**仅当**该变量为 1 **且** issuer 是回环地址（127.0.0.1 / localhost / ::1）时才放行 http。生产保持 HTTPS 强制。该开关不写入 manifest。

## 验证证据

本机用临时 stub OIDC 提供方（实现 discovery / auth / token / userinfo，RS256 签发 id_token）跑通：未登录 `GET /` → 302 `/login`；`/api/v1/session` → 401；`/login` → 200 并渲染登录页；点击登录 → 平台授权 → 回调建立会话 → 进入工作台（`source: lazycat`，`role: admin`，独立空空间）；篡改 state → `/login?authError=state` 并显示“登录状态无效”；退出 → 会话失效，`GET /` 回到 `/login`。`pnpm test:server` 15/15、`pnpm test:web` 1/1、`pnpm typecheck` 0 错误。

## 未验证

懒猫真机 OIDC：`{{ .S.AppDomain }}` 渲染、平台 issuer 连通性、入口隔离、多实例与真机登出均未在设备上验证。本记录不代表真机验收通过。
