# DEC-20260926-003：核对结果标注的持久化方案

- 关联需求：PRD 的 V1-CMR-07、V1-CMR-03；[接入需求](../Requirements/REQ-20260926-003.md)。
- 状态：已由用户授权实施者确定方案；实施与验证分别记录。

## 现状和选择

核对明细是固定的 CSV 资源，原结果不可变。单条及批量标注要在刷新、重启和备份恢复后保留；若写入资源 `metadata_json`，64 KiB 上限不足以存储大结果的逐条标注，且每次编辑都要重写整段 JSON。采用 SQLite 第 3 次迁移增加 `compare_annotations` 表，按 `owner_key`、固定结果资源 ID 和 1 起始明细行号定位。状态只允许“待核实、已核实、忽略”；备注最长 1000 字。标注不改变核对计算分类、原始结果文件或历史任务。

## 数据与访问

复合主键为 `(owner_key, result_id, detail_row)`，另存状态、备注和更新时间。服务端每次读写先核对结果资源归属及其已完成状态；浏览器不能提交 owner。批量写入在一个数据库事务中执行，基于 `updated_at` 做冲突检查；删除标注等同恢复为未标注状态。资源进入回收站后不能新增或读取标注，恢复后原标注仍在。永久删除资源时应删除对应标注，清理流程必须同时记录数量。

这次迁移只新建表与索引，不修改现有三表和已有资源内容。升级前按既有停服一致备份流程保存 SQLite 与资源清单。新程序自动升级版本 2 到 3；旧程序遇更高数据库版本拒绝启动。如需回退，使用升级前的一致快照，而不手动删表或改 `user_version`。

## 实施限制

标注只能解释人工处理状态，不能让不一致记录显示为一致。报告导出应分别呈现计算分类与标注。新的接口和迁移写入后，按用户要求在全部 V1 功能代码完成时统一验证并审查。
