# 本机数据备份与恢复

本流程针对当前 Web 数据目录，要求先停止 API 服务。命令使用 SQLite 的备份接口生成数据库快照，再复制已登记资源和用户配置、任务文件，并用 `backup-manifest.json` 记录每个文件的 SHA-256 与字节数。备份与恢复都只接受**不存在的新目标目录**，不会覆盖原数据。

```bash
cd qsv-web
pnpm --filter @qsv-web/server backup create /path/to/private-data /path/to/new-backup
pnpm --filter @qsv-web/server backup restore /path/to/new-backup /path/to/new-data
```

备份命令会尝试取得数据目录独占锁。如果服务仍在运行，会拒绝备份。取得锁后会先对源目录执行与服务启动相同的恢复检查：完整提交的资源可能由“处理中/中断”改为“可用”，不完整任务可能标为“已中断”，孤儿和过期临时文件可能被清理；因此备份前的检查会改变源目录状态。随后才生成快照。恢复前会逐文件核对清单并检查 SQLite 完整性；任一文件损坏时不会发布恢复目录。恢复完成后，用原先经核验的 qsv 二进制指向新数据目录启动服务，再检查资源、任务、Schema 和行数据。不要只复制 WAL 模式下的 `meta.sqlite` 主文件。

备份包含已登记且可用或在回收站中的资源文件、提交凭据、用户配置和任务目录；不包含尚未完成的上传、临时文件和可重建缓存。尚未完成的 tus 上传最多保留 7 天，跨备份迁移后需要重新选择文件上传。历史旧资源如果没有 `commit.json`，备份仍会核对数据库中记录的内容摘要，但不能追溯认定它们通过了新提交凭据机制。

备份文件包含原始业务数据，当前不加密。请将备份保存在只有授权用户可读的位置，并自行安排加密存储与保留期限。本机已完成“备份→恢复到新目录→启动服务→读取任务、Schema 和含中文及前导零的数据”演练；真机断电、长期归档和升级前恢复演练仍需完成。
